# 智能审计统一架构重构规划

## 项目背景

CodeScan 是一个 LLM 驱动的代码安全审计工具，**核心目标是建设代码审计智能体**。当前存在以下问题：

1. **功能分散**：批量扫描（Scan.vue）和智能审计（UnifiedAudit.vue）功能重叠
2. **高级工具不可用**：4 个高级工具中有 2 个后端 API 完全缺失
3. **架构不统一**：缺少以智能体为核心的统一入口

## 目标定义

### 主要目标

1. **统一入口**：以智能审计为核心入口，支持对话式审计和快速扫描模式
2. **功能完整**：补齐缺失的后端 API（代码结构图、变体分析）
3. **工具互联**：高级工具既可独立使用，也可被智能体自主调用
4. **简化体验**：减少用户认知负担，一个入口完成所有审计任务

### 架构愿景

```
┌─────────────────────────────────────────────────────────────┐
│                    统一智能审计入口                          │
│                  (UnifiedAudit.vue)                         │
├────────────────────┬────────────────────┬──────────────────┤
│   快速扫描模式      │   对话审计模式      │   高级工具模式    │
│   (原 Scan 功能)   │   (Agent 对话)     │   (4 个工具)     │
└────────────────────┴────────────────────┴──────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    UnifiedAuditAgent                        │
│                    (agent_router.py)                        │
├─────────────────┬─────────────────┬─────────────────────────┤
│  代码导航工具    │  安全分析工具    │  高级分析工具           │
│  - search_code  │  - analyze_taint│  - call_chain_analysis │
│  - read_file    │  - check_auth   │  - build_code_graph    │
│  - get_function │  - find_vulns   │  - search_variants     │
└─────────────────┴─────────────────┴─────────────────────────┘
```

## Phase 3：后端 API 补全

**目标**：实现代码结构图和变体分析的后端 API

### 任务 3.1：创建 graph_router.py

- **描述**：实现代码结构图相关 API
- **涉及文件**：
  - `api/graph_router.py`（新建）
  - `api/main.py`（注册路由）
- **API 定义**：
  ```python
  POST /api/graph/build      # 构建代码属性图
  GET  /api/graph/list       # 列出已构建的代码图
  GET  /api/graph/{id}       # 获取代码图详情
  GET  /api/graph/{id}/data-flow  # 获取数据流分析
  DELETE /api/graph/{id}     # 删除代码图
  ```
- **验收标准**：
  - [ ] 所有 API 端点可用
  - [ ] 返回数据格式与前端 CodeGraph.vue 期望一致
  - [ ] 支持 AST、控制流、数据流三种图类型

### 任务 3.2：创建 variant_router.py

- **描述**：实现变体分析相关 API
- **涉及文件**：
  - `api/variant_router.py`（新建）
  - `api/main.py`（注册路由）
- **API 定义**：
  ```python
  GET  /api/variant/patterns          # 获取变体模式列表
  POST /api/variant/search            # 搜索变体
  POST /api/variant/confirm           # 确认变体
  POST /api/variant/generate-rule     # 生成检测规则
  DELETE /api/variant/patterns/{id}   # 删除模式
  ```
- **验收标准**：
  - [ ] 所有 API 端点可用
  - [ ] 返回数据格式与前端 VariantAnalysis.vue 期望一致
  - [ ] 支持基于已知漏洞模式搜索相似代码

### 任务 3.3：实现 Schema 定义

- **描述**：为新 API 创建 Pydantic Schema
- **涉及文件**：
  - `api/schemas_graph.py`（新建）
  - `api/schemas_variant.py`（新建）
- **验收标准**：
  - [ ] 所有请求/响应模型定义完整
  - [ ] 类型注解准确
  - [ ] 包含必要的验证逻辑

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 后端 API 实现复杂度高 | 延期 | 先实现最小可用版本，迭代优化 |
| 前端状态管理复杂 | Bug | 使用 Pinia 统一管理，充分测试 |
| 历史数据兼容性 | 用户体验 | 保留原有 API，新增路由重定向 |
| LLM 调用稳定性 | 功能异常 | 添加重试机制和降级策略 |
